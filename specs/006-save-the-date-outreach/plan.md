# Implementation Plan: Save the date outreach

**Branch**: `006-save-the-date-outreach` (work happens on the session branch) | **Date**: 2026-11-11 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/006-save-the-date-outreach/spec.md`

## Summary

Most of the machinery for the first outreach already exists: the personal link signs in any number of devices, campaigns send by email, text or both, and "save the date" is already a message type with a draft text. This plan adds what is missing. A message-specific landing (a save the date link lands on a save the date page, an invitation link on the RSVP) comes from a fixed-list `next` carried on the personal link, so nothing is stored on the household. A small `settings` addition holds the card's place line and note; the date comes from the wedding event already chosen. A calendar module builds one all-day entry as a standard file and as prefilled Google Calendar and Outlook links, served to signed-in guests, plus a barebones placeholder save the date page at `/save-the-date` that the designer replaces. Staff-marked consent (one number, a batch from the household list, and an import column) is a new database function that only staff can call, recording who, when and how; it widens the rule from the text-message feature and leaves the locked legal pages untouched. The send gets a revised save the date text, a quiet-hours warning, extra preview counts, a readiness list and a test send that does not count as the real send. A per-household "first opened" record drives a "has not opened the site" follow-up filter.

## Technical Context

**Language/Version**: TypeScript (strict) on the Node version in `.nvmrc`, Next.js App Router, React.

**Primary Dependencies**: none new. The calendar file is built by a small tested module (RFC 5545 is short for one all-day entry); the existing libraries cover everything else.

**Storage**: Postgres (Supabase). New migrations add columns to `settings`, `campaigns`, `households` and `household_contacts`, widen two check constraints, replace the audience function and add four functions. No new table. See [data-model.md](./data-model.md).

**Testing**: Jest and React Testing Library (route handlers in the node environment, components in jsdom, fake clients everywhere, no network); pgTAP database tests for the new grants and functions (`npm run test:db`, which needs the local Supabase and Docker; this session has neither, so those run in CI or on a machine with Docker).

**Target Platform**: Vercel production (`hannahandchris.wedding`) and previews; Supabase.

**Project Type**: web application (single Next.js app).

**Performance Goals**: the save the date page answers in one server render; a batch edit of 100 households completes in one database call.

**Constraints**: nothing personal in a calendar entry; no number, address or link in logs; a text sends only to a number whose consent is recorded; the privacy and terms pages are not touched; the placeholder page uses the one existing site stylesheet and adds no design system; the date is a date (all-day), never a time, so no time zone can move it.

**Scale/Scope**: about 100 households, one save the date campaign, a handful of staff.

## Complexity Tracking

| Deviation                                                                                                                             | Why needed                                                                                                | Simpler alternative rejected because                                                                                                   |
| ------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `src/types/database.ts` cannot be regenerated in this session (no Docker); new columns and functions are reached through loose typing | The constitution forbids hand-editing the generated file, and `npm run db:types` needs the local Supabase | Hand-editing the file breaks a constitutional rule; the existing guest and campaign code already uses loose typing for the same reason |
| A third plain page (placeholder save the date)                                                                                        | The couple's explicit exception, so the whole flow can be rehearsed before the design exists              | Building none leaves nothing to land on and the flow cannot be tested end to end                                                       |
| Test sends reuse a campaign with a flag, one household each                                                                           | Reuses the whole send path (same wording, pacing, tracking), which is what makes a rehearsal trustworthy  | A separate test-send path would send through different code, so it could pass while the real send fails                                |
