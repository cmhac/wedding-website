# Implementation Plan: Admin setup guide

**Branch**: `007-admin-setup-guide` | **Date**: 2026-11-12 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/007-admin-setup-guide/spec.md`, with its clarifications.

## Summary

One catalogue of setup steps in code, a pure function that turns the live state of the site into done or open for each, and a banner plus a guide panel in the console layout that show that status. Steps set in the console reuse the existing settings actions; steps set in hosting show instructions and a "Check again". Each staff member's skips, position and whether they have left the guide live in a small per-person table; confirm-by-hand marks live in one shared table. The existing texting banner is replaced by a recommended step. The panel is a native dialog for keyboard and screen-reader behaviour. Mockups: [design/](./design/).

## Technical Context

**Language/Version**: TypeScript (strict), Next.js App Router, React, Node per `.nvmrc`.

**Primary Dependencies**: none new.

**Storage**: Postgres (Supabase). One migration adds two tables with row-level security. See [data-model.md](./data-model.md).

**Testing**: Jest and React Testing Library (pure modules and actions with fakes, components in jsdom, no network); pgTAP for the two tables' policies (`npm run test:db`; needs Docker, so CI runs it).

**Target Platform**: Vercel and previews; Supabase.

**Project Type**: web application (admin console, which is temporary and plain by design).

**Performance Goals**: under 100 ms added to a console page's server response; status needs three parallel reads.

**Constraints**: no secret value ever reaches a page, log or stored row; the page renders without a banner if the status cannot be read; guide state belongs to one person; only the existing plain admin stylesheet is used.

**Scale/Scope**: a handful of staff, about eleven steps.
